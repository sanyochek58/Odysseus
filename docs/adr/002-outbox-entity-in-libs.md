# ADR-002: сущность outbox в libs/common-events

Статус: принято.

Контекст: CLAUDE.md запрещает сущности и репозитории в `libs/`, однако outbox — инфраструктура доставки событий, нужная всем сервисам одинаково. Дублирование кода в каждом сервисе нарушает DRY; расхождения привнесут баги.

Решение: исключение для инфраструктуры outbox. В `libs/common-events` живут: сущность `Outbox`, `OutboxRepository`, `OutboxService` с `@Transactional` в отдельном бине, `OutboxRelay` (публикатор). Таблицы `outbox` и `processed_events` создаёт Liquibase каждого сервиса через шаблон `db/changelog/common-events/outbox-changelog.yaml` (поставляется библиотекой). Бизнес-сущности и репозитории остаются в сервисах.

Отвергнуто: дублирование (расходятся версии), внешняя библиотека (сложность версионирования), сущность в каждом сервисе (неподдерживаемо).

Последствия: изменения схемы outbox касаются всех сервисов, правятся только добавлением полей (backward-compatible). Тенант не хранится в outbox (публикатор работает в системном контексте). Для новых сервисов outbox подключается по шаблону из `docs/guides/outbox.md`.
